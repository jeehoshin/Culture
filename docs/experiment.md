# 데이터 수집 실험 결과

실행일: 2026-10-17

초기에는 외부 API 키 없이 공식 명세의 응답 필드에 맞춘 fixture 7건(의도적으로 같은 행사 1쌍 포함)으로 파서와 품질 분석기를 검증했다. 인증 없이 웹 페이지를 크롤링해 대신 채우지는 않았다. 이후 KOPIS 키가 준비되어 아래 실데이터 표본 실험을 추가했다. 문화포털 실험은 아직 키가 없어 대기 중이다.

- 제목·장소·시작일·종료일·가격 문자열 완전성: 각 100% (fixture 기준)
- 중복 후보: 1쌍 탐지
- 같은 행사에서 `[서울]`, 구두점, 장소 띄어쓰기 차이가 있어도 점수 1.0
- 가격: 무료, 단일 가격, 좌석 등급별 범위, 미정 처리 테스트 통과

이 수치는 실제 API 품질을 뜻하지 않는다. `events` 스키마는 MVP 구현용 **잠정안**이며, 실데이터 실험 후 가격/주소/상세 URL의 실제 결측과 필드 변형을 반영해 확정해야 한다.

## KOPIS 실데이터 표본 결과

실행일: 2026-10-17, 범위: 서울에서 현재~3개월 내 진행되는 연극·뮤지컬, 균형 표본 각 20건

- 총 40건: 연극 20건, 뮤지컬 20건
- 상태: 공연예정 35건, 공연중 5건
- 제목·장소·시작일·종료일·가격·시설주소·장르·상태 완전성: 모두 100%
- 가격 파싱: 유료 38건, 무료 2건, 미정 0건
- 제목·장소·기간 기반 중복 후보: 1쌍(점수 0.9679). 자동 병합하지 않고 수동 검토 대상으로 유지한다.

목록만으로는 가격과 주소가 없으므로 공연 상세(`pblprfr/{id}`)와 시설 상세(`prfplc/{id}`) 호출이 필요하다는 점을 실데이터로 확인했다. 이 결과는 전체 모집단 통계가 아니라 정규화 필드 설계를 검증하기 위한 40건 표본이다.

```bash
cd backend
.venv/bin/python -m scripts.run_experiment --source fixtures
# KOPIS 키만 준비된 경우
.venv/bin/python -m scripts.run_experiment --source kopis
# KOPIS와 문화포털 키를 모두 넣은 뒤
.venv/bin/python -m scripts.run_experiment --source live
```

첫 실데이터 보고서에서 장르별 건수, 필드 완전성, 서울 외 데이터 혼입, 가격 파싱률, 교차 출처 중복 후보와 오탐을 확인한다. 최소 100건을 눈으로 표본 검토한 뒤 자동 병합 임계값을 조정한다.
